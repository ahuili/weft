# Weft —— 以「事情」为中心的 macOS 窗口工作台

> Weft（纬线）：把散落在各个 App、各块屏幕上的窗口，按「你正在做的事」织在一起。

## 0. 第一性原理：用户真正要的是什么

用户不是想「管理窗口」，而是想 **随时、零成本地回到某件事的现场**。

把痛点拆到底，只有三个根因：

| 根因 | macOS 现状 | 后果 |
| --- | --- | --- |
| **组织单位错了** | 系统只认「App」和「桌面(Space)」，不认「事情」 | 点 Dock 的 Chrome 是按 App 轮转窗口；同一件事的窗口散在多个 Space |
| **布局绑在物理屏幕上** | Space 跟显示器绑定，窗口坐标是绝对坐标 | 插拔外接屏 = 布局被系统重排，回不去 |
| **寻址成本高** | 找窗口只能靠「翻」：⌘Tab 翻 App、⌃→ 翻桌面、点 Dock 一个个跳 | 窗口越多，找一次越慢（O(n)） |

所以产品要做的三件事：
1. **把「事情（Context）」变成一等公民**：窗口属于某件事，而不是属于某个桌面/屏幕。
2. **布局 = f(事情, 当前显示器组合)**：布局是声明式的，屏幕变化时自动重新求解，而不是让系统乱放。
3. **寻址从「翻」变成「说」**：按名字搜（拼音/模糊），或者用自然语言说（AI）——O(1)。

## 1. 参考产品取舍

| 产品 | 值得借鉴 | 不足 / 我们的差异 |
| --- | --- | --- |
| Tangrid | 拖拽吸附带落点预览；搜索式窗口切换（拼音）；Dock 悬停预览；保存 Workspace 并可「缺窗口时自动拉起」；Repair Permissions；悬浮为主、平铺可选 | Workspace 仍绑定系统 Space；插拔屏行为未说明；没有「事情」概念、没有 AI |
| AeroSpace | 虚拟工作区不依赖系统 Space（把非当前窗口挪出屏幕），插拔屏稳定 | 强平铺、全靠配置文件，门槛高 |
| AltTab / Raycast Switch Windows | 窗口级切换 | 只解决「找」，不解决「放」 |
| Moom / Stay | 按显示器组合保存恢复布局 | 窗口身份识别弱，标题一变就失效 |

## 2. 产品形态

常驻菜单栏的原生 App，3 个主入口，全部键盘优先：

```
⌥Tab          万能切换器  搜窗口 / 搜事情 / 执行命令（一个框搞定）
⌥⇧Space       AI 指令     「把 XX 相关的窗口拉到左边」「整理一下」
⌥1…⌥9         一键回到第 N 件事
```

### 2.1 核心概念

- **Window**：一个真实窗口。身份 = `bundleID + 标题特征 + 创建顺序`，标题变化时用相似度跟踪，而不是 CGWindowID（重启就变）。
- **Context（事情）**：一组窗口 + 它们的布局。可手动建、可 AI 推荐（例如根据 Chrome 标题/域名、终端 cwd、文档名聚类）。一个窗口可以属于多件事。
- **Display Profile**：当前接了哪些屏 —— 用「屏幕型号+分辨率+排列」做指纹。
- **Layout**：`Context × DisplayProfile → 每个窗口的位置`，位置用 **相对坐标（占屏比例）+ 目标屏角色（主屏/外接左/外接右）** 存，不存绝对像素。

### 2.2 功能分层

**P0 —— 原型（本次实现）**
1. **万能切换器**：窗口级列表，拼音+模糊搜索（`wx` → 微信，`gh pr` → GitHub PR 那个 Chrome 窗口），按最近使用排序，显示所在屏幕。回车直达（跨 Space 也能拉起）。
2. **显示器感知的布局快照**：
   - 一键保存「当前显示器组合下的布局」。
   - 检测到插拔屏 → 去抖 1.5s → 自动套用该组合的布局；没存过就做「智能降级」：外接屏上的窗口按比例缩放到主屏，并记住它原本在哪，等外接屏插回来自动归位。
3. **撤销**：任何自动/AI 操作前自动快照，菜单栏一键撤销。
4. **AI 指令**：自然语言 → 工具调用（列窗口/聚焦/移动到区域/最小化/存布局）→ 执行，可撤销。
5. **模型来源**：自动发现本机 Magpie（`127.0.0.1:3425`，OpenAI 兼容，可直接列出模型），菜单里选；也可自定义任意 OpenAI 兼容端点。
6. **CLI**：`weft list / save / restore / ai "..."`，方便脚本化和 Raycast 集成。

**P1 —— 好用**
- Context 一等公民：⌥1…⌥9 直达、切换器里按事情分组、「事情」的窗口不在时可自动拉起（打开 URL / 运行命令，借鉴 Tangrid launch action）。
- 修 Dock：点有多个窗口的 App 时，弹出该 App 的窗口卡片而不是轮转。
- 拖拽吸附（按住修饰键拖动，显示落点预览）、键盘分屏。
- 虚拟工作区（AeroSpace 式：非当前事情的窗口移到屏幕外），彻底摆脱系统 Space。

**P2 —— 智能**
- AI 自动建议 Context：「你最近在做 3 件事：A、B、C，要分组吗？」
- 工作时间线：「回到昨天下午 3 点的工作台」。
- 语义找窗口：「刚才那篇讲 K8s 的文章」（基于标题，必要时可选截图 OCR）。
- 专注模式：一键隐藏与当前事情无关的窗口。

## 3. AI 设计原则

1. **确定性的事不交给 AI**：快捷键、布局恢复、切换都走本地规则，毫秒级、100% 可预期。AI 只负责「理解意图 → 生成操作计划」。
2. **AI 只能调用白名单工具**，每次执行前自动快照，可一键撤销。
3. **隐私**：默认只发送 `App 名 + 窗口标题 + 屏幕信息`，不发截图；可设置标题脱敏（屏蔽聊天 App 标题）。优先推荐本机网关/可信端点。
4. **模型可插拔**：OpenAI Chat Completions 协议 + tools；来源 = Magpie 发现 / 自定义。

## 4. 技术选型

**结论：Swift 原生（AppKit + 少量 SwiftUI），SwiftPM 构建。**

窗口管理器 90% 的代码是在和系统 API 打交道：

| 能力 | API |
| --- | --- |
| 列窗口 | `CGWindowListCopyWindowInfo` |
| 读/移动/缩放/聚焦其他 App 的窗口 | Accessibility `AXUIElement`（需辅助功能权限） |
| 监听窗口创建/销毁/聚焦 | `AXObserver`、`NSWorkspace` 通知 |
| 监听插拔屏 | `NSApplication.didChangeScreenParametersNotification` / `CGDisplayRegisterReconfigurationCallback` |
| 全局快捷键 | Carbon `RegisterEventHotKey` |
| 窗口缩略图 | ScreenCaptureKit（需录屏权限，可选） |

关于 [egoist/mygo](https://github.com/egoist/mygo)：它是用 Go 写跨平台桌面 App 的框架（WebView 或 GPU 自绘原生 UI、纯 Go 无 cgo），很适合「跨平台的普通桌面应用」。但本项目：
- 核心能力只存在于 macOS，跨平台收益为零；
- 文档未提供 AXUIElement / CoreGraphics 绑定，需要自己做 FFI，热路径（切换器要求 <50ms 出现）多一层桥接；
- 本机 Go 版本为 1.17，mygo 要求 Go 1.27+。

因此核心用 Swift。若以后要做「漂亮的设置页 / AI 控制台」，可以把它作为独立前端，用 mygo 或 WebView 通过本地 socket 调用 Weft 核心——这是解耦后的可选项，不是现在的必需品。

## 5. 架构

```
Weft.app (菜单栏常驻, LSUIElement)
├── WeftCore         纯逻辑 + 系统封装
│   ├── WindowInventory   CGWindowList + AX 合并出窗口列表
│   ├── AXWindow          聚焦 / 移动 / 缩放 / 最小化
│   ├── DisplayProfile    显示器指纹、屏幕角色
│   ├── LayoutStore       按 Profile 存相对坐标布局（JSON）
│   ├── WindowMatcher     标题相似度跟踪窗口身份
│   ├── FuzzyMatcher      拼音 + 模糊打分
│   └── UndoStack
├── WeftAI
│   ├── ModelConfig       Magpie 发现 / 自定义端点
│   ├── ChatClient        OpenAI 兼容 + tools
│   └── WindowAgent       工具定义 + 执行循环
└── Weft (App)
    ├── HotKeys / ScreenWatcher
    ├── SwitcherPanel     ⌥Tab
    ├── CommandPanel      ⌥⇧Space
    ├── StatusMenu        模型选择、保存/恢复/撤销
    └── CLI               weft list|save|restore|ai
```

数据：`~/Library/Application Support/Weft/`（`config.json`、`layouts.json`）。

## 6. 成功标准

- 找到任意一个窗口：≤ 3 次按键、< 1 秒。
- 拔掉外接屏后：窗口全部可见、无重叠到屏幕外；插回 2 秒内恢复原布局。
- AI 指令：常见整理意图一次成功率 > 80%，所有操作可撤销。

## 7. v0.2 交互重设计（根据第一轮试用反馈）

反馈：①装好了却看不见、权限总显示没有；②快捷键太多、和别的 App 冲突；③AI 用来「把 X 挪到右边」没意义，打字的时间都够自己拖了；④要有创意、要好看，比如左侧悬浮窗口缩略图。

### 7.1 只留三个入口

| 入口 | 设计理由 |
| --- | --- |
| **双击 ⌥ → 总控** | 双击修饰键不会和任何组合键冲突，单手就能按（Spotlight / Raycast 占的是 ⌥Space、⌘Space）。所有低频操作都收进总控，在面板里用不带修饰键或带 ⌘ 的单键完成，不用再记全局快捷键 |
| **⌥Tab → 快速切换** | 复用 ⌘Tab 的肌肉记忆，但单位是「窗口」，顺序是真实使用顺序 |
| **鼠标碰左边缘 → 侧边栏** | 零按键。用 1px 感应条 + 0.22 秒停留判定，避免误触 |

删掉了 v0.1 里所有 ⌃⌥ 开头的快捷键：分屏、保存/恢复、撤销都挪进了总控。

### 7.2 AI 的定位：学习习惯 + 整理归类，不做遥控器

- **习惯（本地统计，不经过 AI）**：记录窗口之间的切换（停留超过 1.5 秒才算一次）、使用时段、累计时长。预测分数 = 最近使用（30 分钟衰减）+ 使用频率 + 时段吻合度 + 从当前窗口切过去的概率。这个分数决定「接下来可能要去」、⌥Tab 的顺序和侧边栏推荐。
- **整理（调用 AI）**：把窗口标题和「经常来回切的窗口对」交给模型，让它按「事情」分组并命名，先预览、你接受后才生效。实测 glm-5.3-flash 能把「GitHub PR + 项目终端」归成「Weft 开发」，把「Gmail + 微信」归成「日常沟通」。
- 后续：新窗口打开时按习惯自动归位；定期提醒「这 5 个窗口 3 天没碰，要停靠吗」。

### 7.3 视觉

- 总控：全屏毛玻璃 + 实时缩略图卡片。按事情用彩色分区；选中的卡片会放大并发光，弹簧动画。
- 侧边栏：从左边滑出的玻璃面板，三个区：固定、推荐、停靠。
- **停靠**：一种新的「收起」方式。把窗口挪到屏幕外（比最小化快，没有动画），缩略图留在侧边栏，点一下回到原位。相当于一个由你自己控制的「台前调度」。

### 7.4 可见性与权限

- 首次启动以及权限不全时，弹出看得见的引导窗口：实时显示两项权限的状态，提供「去授权 / 重置授权记录 / 重启 Weft」按钮。
- 签名改用本机自签名证书，签名身份固定，重新编译后授权不会失效（v0.1 用的临时签名每次编译都会变，这是「打开了开关还显示没权限」的原因）。

## 8. v0.3：舞台模式 —— 换一种工作方式（根据第二轮反馈）

### 8.1 核心洞察
窗口乱，不是因为开得多，而是因为**所有窗口都在同时争夺注意力**。用户真正要的不是「把 30 个窗口排整齐」，而是「眼前只有现在要用的 1~3 个，其余的不消失、随时叫得回来」。

### 8.2 舞台模式（Stage）
- **台上 / 后台**：每块屏幕一个舞台，只上台 1~3 个窗口；其余窗口退到后台（挪到屏幕外，不最小化，所以进出都是瞬间完成、状态完整保留）。
- **版式**：专注（单窗居中留白）、铺满、左右（5:5 / 6:4 / 7:3 可循环）、一主两辅（左主 + 右侧上下叠）、三栏（中间主，宽屏用）。窗口不够时自动退化（三栏剩两个 → 左右；剩一个 → 专注）。0 号槽位永远是「主位」，可以镜像到右边、主副互换。
- **跟随你**：不管用什么方式切到一个窗口（⌥Tab、侧栏、总控、⌘Tab、点 Dock、点通知），它都会上台，替换掉你正在用的那个槽位；被替换的退到后台。新开的窗口也自动上台。所以「不管多乱，当前用的永远是干净的」。
- **保护**：小于 440×300 的窗口（计算器、小浮窗、设置面板）不参与舞台，原样悬浮。可选的「幕布」盖住桌面图标，并吃掉桌面点击，避免 macOS「点按墙纸显示桌面」把窗口全部推开。退出舞台时，后台窗口回到进入前的位置；插拔屏时自动先退出舞台再恢复布局；Weft 退出 / 崩溃重启都会把后台窗口放回。
- **和「事情」结合**：在舞台里进入一件事 = 把这件事最近用过的 1~3 个窗口按合适的版式请上台。

### 8.3 边缘侧栏 → 「后台」
从「几个常用缩略图」升级成**所有窗口的指挥台**：
- 一滑出就能直接打字搜（拼音），↩ 打开第一个。
- 舞台控制条 + 台上的窗口（可以请下台）。
- 「事情」胶囊一点即切；「常一起用」一键并排（纯本地习惯，不用 AI）。
- 📌 固定 / ✨ 接下来 用缩略图；其余窗口**按 App 叠放**，多窗口的 App 可展开。
- 悬停任何一项，侧栏旁浮出大预览；◧ ◨ 直接放主位 / 副位（非舞台时 = 左 / 右半屏）。
- 可以放左边缘、右边缘或关闭；弹出延迟可调。

### 8.4 AI 排布建议
AI 不做「把 X 往右挪」这种指令，而是当**排布顾问**：读窗口、屏幕尺寸、当前窗口、最近使用顺序、来回切换的窗口对、已有的事情，给出 1~3 套侧重不同的方案（如「专注写代码」「边查边写」「处理消息」），每套画成按真实比例的屏幕缩略图。可以「进入舞台」（其余退后台）或「只摆放」（其余不动，可撤销）。输出被严格校验：不存在的窗口 / 屏幕丢掉，超出版式容量的截断。

### 8.5 首次引导与设置
同一套页面，两种用法：首次按步骤走（欢迎 → 权限 → 快捷键 → AI → 舞台与侧栏 → 完成），之后作为设置窗口用标签页切换。
- **快捷键**：每个功能（总控 / 舞台 / 快速切换）都可以选「双击某个修饰键」（区分左右，默认右 ⌥ / 右 ⌘，几乎不冲突）、录制任意组合键、或不用；每个选项写明冲突风险；页面上有实时检测，双击后立刻显示识别结果；同一触发被两个功能占用、或被别的 App 抢注时会提示。
- **AI 模型**：不再默认从 Magpie 导入，由用户自己选：Magpie（本机）、DeepSeek、通义千问、Kimi、智谱、豆包、OpenAI、OpenRouter、Ollama、自定义 OpenAI 兼容端点。填 Key（存钥匙串）→ 拉取模型列表 → 测试连接。不配置也能用除 AI 以外的所有功能。

### 8.6 同一个 App 的多个窗口
两个「微信」通常是同一个 App 的两个真实窗口（主界面 + 单独弹出的聊天 / 公众号 / 图片窗口），点哪个就去哪个。现在每个多窗口 App 的窗口都会带一句区分说明：「主窗口 · 左侧 · 900×700」「小窗 · 右上 · 380×520」，后台侧栏里同 App 叠放成一组。


## 9. v0.4：多屏舞台、整理、身份

### 9.1 名字和图标
Weft = 纬线：在经线之间穿梭、把散线织成布的那根线。图标：经纬交织（看得出一上一下），正中一扇发光的窗口 = 「不管多乱，你正在用的那个是干净的」。菜单栏图标是同一意象的简化版（回字形的交织边框 + 中间一扇窗），舞台模式时窗口变实心。

### 9.2 多屏舞台：屏幕有分工
实际工作里每块屏都有自己的角色（大屏写代码 / 笔记本放聊天）。所以：
- 每块屏一个独立的舞台和版式；
- 每个窗口有「家」：叫回来回自己的屏，不跟着「最近操作的屏」乱跑；
- 想换屏必须是明确动作：在那块屏的面板里 ◧ ◨，或者直接把窗口拖过去（Weft 跟随并记住新家）；
- 面板开在哪块屏，控制条就管哪块屏；多屏时控制条顶部能切换。

### 9.3 实机排查出来的版式问题（v0.3 「布局不对」的根因）
- Chrome / Electron 在 AXEnhancedUserInterface 打开时拒绝「变大」，只保持左下角对齐 → 改尺寸前临时关掉（Rectangle / yabai 同样的做法）；顺序改为 尺寸→位置→尺寸。
- 改尺寸是异步的：0.35s 后读回，没到位重试一次；还是更宽 = App 有最小宽度，按列模型重分；尺寸纹丝不动 = 固定尺寸窗口，请出舞台原样悬浮。
- 后台窗口原来停在「所有屏幕的右下角」，外接屏在上方时这个点不在任何屏上，macOS 会把窗口拽回来 → 改为停在自己那块屏外侧、外面没有其他屏的角。
- 被 kill 时也会把后台窗口放回原位（SIGTERM 处理）。

### 9.4 整理
规则（即时）+ AI（深度判断「事情办完没」）两层；所有建议先勾选后执行。误伤防护：有改动的未命名文档不算空；终端 / 编辑器的同名窗口是不同会话；编辑器类的 AI「关闭」自动降级为「收进后台」；AI 建议的关闭默认不勾；聊天软件不默认退出。

### 9.5 比「进总控找」更快：数字槽位（已做）
三个候选方向：数字槽位、字母跳转、语义召回。先做数字槽位：最快、最确定、和舞台天然搭配。
- ⌥⇧n 钉住（总控里钉选中的那个），⌥n 直达；已经在 n 号上再按 = 跳回刚才那个（Harpoon / 双键来回）。
- 绑定 = 窗口 ID + App + 标题：ID 失效时按「同 App 同标题 → 同 App 最像的标题」认领，不抢别的槽位的窗口；App 没窗口就打开 App。
- 修饰键可选 ⌥ / ⌃ / ⌃⌥ / 关（⌥数字会占掉几个特殊符号的输入）。
- 后续可做：字母跳转（贴字母、按字母上台）、语义召回（「昨天那个报价表」）。

### 9.6 补位与换人、几处实机问题
- 补位顺序：常一起用（习惯里来回切换 ≥2 次）→ 这块屏的窗口 → 最近使用；实测最小宽度放不进副位的跳过，放进去才发现放不下的自动换下一个。
- 换人：不弹对话框打断，而是在屏幕上那个位置浮一条候选，点了就换、不理就消失（默认已经是合理的人选，换人是可选动作）。
- App Store 盖在上面：它会自己把窗口拉回屏幕，而后台记录还写着「藏好了」→ 定期核对真实位置，拉回来的再藏，屡藏屡回改最小化；换版式时立刻核对一次。
- 锁屏：AX 看不到窗口时曾会被当成「全关了」，清掉后台记录导致窗口丢在屏幕外 → 存在性改问窗口服务器，锁屏时不对账、不退出、不删记录。
- 性能：数字槽位走缓存句柄直达（~60ms，原来 300ms+）；舞台对账每轮只枚举一次窗口。

## 10. v0.5：格子舞台、整理桌面、流畅度（根据第四轮反馈）

反馈：① 有点卡；② 舞台分屏有时不分、分得不对，要重构，参考 Tangrid 这类固定位置的方案，切版式时炫酷地弹出候选，但又怕死板；③ Mac 上十几个空桌面，希望 AI 像整理书桌一样整理不同屏幕、不同桌面上的窗口；原来的 AI 分组「分了一个大的」，不知道有什么用。

### 10.1 卡顿的原因和解法
- 原因：每读一次全部窗口要逐个问 20 多个 App（~190ms），而且在主线程；舞台每 2 秒一次、换版式一次要读好几遍。
- 解法：按 App 缓存窗口，靠 AX 通知只重读有变化的 App，位置从窗口服务器取 → ~14ms；排版校验只取位置（~1ms）；焦点切换靠通知即时响应。
- App 卡住 / 锁屏时读失败：保留上一次的结果，不当成「窗口都关了」。

### 10.2 舞台重构：格子模型
- 一条规则：每块屏 = 版式 + 格子，格子放一个窗口或空着。不再自动补位、不再自动降级版式（这两条是「不分 / 分不对」的根源）。
- 版式盘（快捷键弹出，数字键选，6 种含四宫格）→ 空格子里弹候选缩略图（点 / 数字 / 拼音搜）。
- 不死板的三招：⌘Tab 切来的窗口换进当前格子（有空格子先填空格子）；⌥ + 滚轮原地轮换某个格子的窗口；锁格。
- 拖进别的格子 = 两个窗口换位。
- 有最小宽度的窗口：多分宽度、候选里标出、转轮跳过；事后才弹宽的 App（企业微信）在对账时补学。

### 10.3 整理桌面（取代 AI 分组）
- 桌面地图：读出所有调度中心桌面和上面的窗口。实测本机笔记本 20 个桌面里 15 个是空的。
- 删空桌面 / 合并成每屏 1 个：驱动调度中心里每个桌面按钮的「移除桌面」辅助功能动作（不需要关 SIP）；删有窗口的桌面时系统把窗口挪走，不关闭。
- 场景：AI 看所有桌面上的窗口 + 使用时长 + 来回切换，给 3~6 个小而具体的场景，每个带每块屏的版式；先试摆，保存后一键摆出。分组终于「落地」成屏幕上看得见的东西。
- 选择 B 方案：每块屏只留一个系统桌面，用 Weft 的场景代替翻桌面（系统桌面之间挪窗口没有公开接口，场景切换完全可控）。

### 10.4 v0.5.1（第五轮反馈）
- 扩展屏上舞台不生效：原因是版式盘第一次弹出时把「操作哪块屏」永久钉在了笔记本上。改为版式盘弹在鼠标所在的屏，选的版式、比例、翻转都作用于那块屏。
- 侧栏：离屏幕边缘留 6pt（笔记本圆角不再挡住）；新增快捷键（默认双击左 ⌥），快捷键打开时不跟着鼠标收起、点别处才收；按数字直达，⇧数字 给鼠标下的窗口编号，搜索结果也带数字。
- 记忆（新）：本机记录「几点、哪几个窗口在一起、怎么摆」；AI 每天把统计复盘成可编辑的笔记，所有 AI 功能都先读笔记；空数字推荐最常用的窗口；侧栏「此刻」按时间提示常用场景、把常见摆法存成场景。
- 设计取舍：推荐编号不会自动改已有的号码（肌肉记忆最重要），只填空号码，而且要你点一下才生效；提示只出现在侧栏顶部，不弹窗打扰，关掉一周不再提。

### 10.5 v0.5.2（第六轮反馈：舞台不稳定、侧栏被挡、Telegram 一直在右边）
实机排查找到的原因（都已修复并在两块屏上实测）：
- **Telegram 一直挂在右边**：三栏版式在笔记本上侧栏只有 436 宽，低于「小浮窗」门槛 440。窗口一旦被摆窄，就被当成小浮窗：不藏、⌘Tab 过去也不上台。改为门槛降到 360×260，且上过台的窗口永远算正常窗口。
- **最小化一个窗口，舞台整个退出**：最小化会让 Dock 变长，系统发「屏幕参数变了」，Weft 当成插拔屏退出舞台。改为只有屏幕真的变了（哪几块、位置、尺寸）才退出，Dock / 菜单栏变化只原地重排。唤醒同理。
- **切过去没反应**：Weft 换下「正拿着键盘焦点」的窗口后，焦点还停在已经退到后台的窗口上，再 ⌘Tab 到同一个 App 系统认为焦点没变。改为 Weft 每次换人后把焦点交给台上当前格子的窗口；焦点停在后台窗口上时每秒重新判断。另外 Weft 刚摆完窗口那 0.8 秒内的切换以前会被直接丢掉，现在会等一下再处理。
- **手动动一下就乱、回不去**：以前只处理「拖进别的格子」，挪歪了、拉宽了、App 自己跑偏了都没人管。新增磁吸（见 README）、撤销、一键归位。
- **底层 bug**：读窗口位置的快速接口（CGWindowListCreateDescriptionFromArray）参数传错，一直什么都读不到，导致「摆完校验、重试、学最小宽度」实际上从没生效。修好后顺带去掉了一个靠它判断「改不了尺寸就踢下台」的规则（Electron 改尺寸是异步的，会误杀）。
- **侧栏左边被挡**：不是屏幕边缘，是舞台控制条一行太宽（约 350pt）超过侧栏宽度，SwiftUI 把整列居中、两边裁掉。侧栏的舞台面板改成分行（屏幕 · 撤销 · 归位 / 版式 / 比例 / 每个格子一行），内容固定 276 宽靠左对齐，万一再超也只裁右边。

设计取舍（参考 Mac 用户已有的习惯）：
- 松手才处理，按住时绝不抢；不是你拖的（App 自己跑偏）等 1 秒稳定了再吸回，最多试两次，App 不肯就算了。
- 系统原生手势（双击标题栏、绿色按钮、⌘M、⌘H、⌘W）都保留原本的含义，只是在舞台里有合理的后续：铺满就让它铺满，最小化 / 隐藏 = 请下台，关掉 = 上一个回来。
- 调试：`Weft ctl dump` 末尾带最近的舞台事件日志（自动上台、吸回、换位、改比例、撤销……），`Weft ctl settle <file>` 看磁吸状态。

## 11. v0.6：场景代替系统桌面（第七轮反馈）

反馈：整理桌面得到 6 个场景，以为是「6 个系统桌面各放一个场景」；点了不生效，桌面还乱了；想要一个按键就能左右滑选场景截图的切换器；场景不要绑死笔记本 / 外接屏，能自由组合；AI 场景要能编辑；拔掉外接屏场景归到笔记本，插回来自动恢复。

原因：
- 不生效：6 个场景里的窗口大多在别的系统桌面上（Excel、Navicat、Ghostty、几个 Chrome），macOS 不让别的 App 把窗口挪到别的桌面或在别的桌面上摆窗口（yabai 这类要关 SIP），被跳过了。
- 乱：舞台开着时滑到别的系统桌面，Weft 把那个桌面上的窗口都当成「新冒出来的杂窗口」藏到屏幕外。

决定：**场景就是 Weft 的桌面**，不去驱动系统桌面。
- 场景只管一块屏、不绑屏幕；组合 = 几个场景各回上次的屏（屏不在就放到别的屏、屏不够就少摆）。旧的跨屏场景自动拆分（名字用 AI 给的分屏名，或里面的 App 名）。
- 场景切换器：截图卡片 + 左右滑；再按快捷键 = 下一个；默认停在「这块屏现在的场景」的下一个，回车就是「换一个」。
- 编辑 = 摆出来、调好、按 U 更新（所见即所得，不另做编辑器）；E 改名、N 新建、C 存组合、⌫ 删除。
- 插拔屏不再退出舞台：拔掉的屏的舞台记着，插回来恢复；剩下的屏原地重排。
- 舞台记住每块屏所在的系统桌面，你滑到别的系统桌面时在那块屏上暂停。
- 场景里在别的系统桌面上的窗口标「别处」，切换器提示合并桌面（需要确认，合并只是删空桌面，窗口被系统挪过来，不会关）。

没实测的：真插拔外接屏、滑到别的系统桌面（逻辑有离线测试覆盖）。

### 11.1 v0.6.1（第八轮反馈：窗口后面还有东西、编辑太麻烦、点 Dock 会换掉右边的窗口）
- **窗口后面还有别的软件**：是 magpie 这类「菜单栏 App」（没有 Dock 图标）的主窗口，Weft 以前只管普通 App，藏不掉。改为有正常大窗口的菜单栏 App 也管。
- **锁屏时的假数据**：锁屏 / 屏保时 AX 会回一堆没有窗口号的假窗口，以前会被缓存成「这个 App 没有窗口」。改为当成读失败、保留上次结果。
- **编辑**：去掉 U / N / C 这些要记的键，改成场景工作台（拖窗口进格子）+「活的场景」（屏上的调整自动存进正摆着的场景）。没有场景时启动就打开工作台。
- **点 Dock**：先看这个窗口在不在某个场景里（在就切过去），不在就单独开新场景，再用顶部卡片问要不要放进刚才场景的某一块（鼠标停哪块，屏幕上那块亮紫框）。替换必须是你点出来的，不再自动发生。
- 场景按格子摆：某一格的窗口关了 / 在别的桌面上，那一格空着，别的窗口不挪位。
- 实测后又修了：浮层卡片里的格子第一下点击不响应（改成按钮）；点场景里的窗口时，场景回到它上次摆的那块屏（大屏的三栏不会挤到笔记本上）；App 自己变宽（最小宽度）以前会被误当成「你拉了中间的边」而改掉比例、还被存进场景，现在只有刚松开鼠标的才算你拖的。

### v0.6.2 复查修复

- **场景悄悄少窗口**：另一块屏摆了个也用微信的场景（微信被借走），或者你退出 / 最小化了某个 App，下次你一调整，原场景就被存成「那一格空着」，永远少了它。现在只有「你把它请走」（窗口还开着、没最小化、也没上别的屏）才会从场景里去掉。
- **拔屏后点外接屏场景里的窗口**：以前会往那块已经拔掉的屏上摆（窗口从后台拿出来却没地方放）。现在拔掉的屏不算「正摆着」，场景摆到你正在用的屏上。
- **插回外接屏**：拔着的时候把大屏的场景摆到了笔记本上，插回来时大屏场景回大屏、笔记本回到拔之前那个；笔记本上换成了无关场景的就不动。
- **拉边改比例的判定再收紧**：必须是鼠标按着的时候窗口就离开了格子才算你拖的；只是点了一下、App 随后自己变宽（打开侧栏等）不会再被当成拉边。
- **单独场景不会越积越多**：点 Dock 自动开的单独场景最多留 6 个，多了收掉最久没用、没摆着、你也没改过的；改过名 / 调整过的就是正经场景，不会被收。开单独场景失败时不留空壳。
- 空场景摆不出来时提示「还没放窗口」，而不是「窗口都关了」；场景成员里不再混入空格子占位。
- **「有时候会卡」**：实测抓到主线程有约 1/5 的时间在做无用功。某个窗口吸不回格子（外接屏上一个窗口比格子高 20px，App 不肯缩）后，Weft 每 0.35 秒还要把所有 App 的窗口完整读一遍，只为了日志里写个窗口名。现在名字只在真写日志时才查；吸了两次还不肯的窗口不再反复处理；问「这个进程是不是普通 App」的跨进程调用按进程缓存。舞台模式下 CPU 从约 20% 降到 0.3%~1.5%。
- **内存越用越大**：关掉的窗口的缩略图从不清理（跑了 8 小时到 540 MB）。现在每次刷新都扔掉已关窗口的缩略图。

### v0.6.3 像切系统桌面一样切场景

Weft 接管后实际上只有一个系统桌面，所以把切桌面的两个老习惯拿来切场景（只在舞台模式下接管，没开舞台时还是系统的）：
- **⌃← / ⌃→**：用 HID 层的事件截取抢在系统「切换桌面」快捷键之前拿到按键（Weft 本来就有辅助功能权限）。按住 ⌃ 浮出截图卡片（不抢键盘焦点），连按选，松开 ⌃ 摆出来；Esc 不换。换的是键盘焦点所在的屏。
- **四指左右滑**：读触控板原始触点（私有框架 MultitouchSupport，只读不拦截）。手指横向每走约 1/10 触控板宽度挪一张卡，竖着滑不管（那是调度中心）；抬手摆出来。换的是鼠标所在的屏。系统自己的四指滑照常发生（一个桌面时只是轻弹一下），可以在触控板设置里改成三指或关掉。
- 卡片只列场景（不含组合和「新场景」），起点是这块屏现在摆着的场景；选到的就是现在这个时松开什么都不做。
- 实测：⌃→ 由 Weft 自己发出的按键验证了截取、卡片前进一格、松开 ⌃ 摆出下一个场景、再切回来都正常。外部进程（没辅助功能权限）发的按键会被系统直接丢掉，测不出来。四指滑需要手实测。

### v0.6.4 手势反馈修复

- **四指上滑（调度中心）后窗口被拉到右下角、还变小**：调度中心开着时，窗口服务器报的是调度中心里缩略图的位置，Weft 以为藏在后台的窗口被拉回了屏幕，当场又把它们一个个藏回右下角，藏的时候用的是缩略图的尺寸，所以有的窗口被改小了。现在调度中心开着时（程序坞的辅助功能树里出现 "mc" 组）舞台整个暂停，关掉后再等 1.2 秒。实测打开 / 关掉调度中心前后，所有窗口的位置和尺寸完全一致。调度中心里本身还是会看到藏着的窗口（它们是真实窗口，系统照样列出来）。
- **⌃← / ⌃→ 第一下只浮出卡片**：以前第一下就选到了下一个，松开 ⌃ 就换走了。现在第一下停在这块屏现在的场景上，按住 ⌃ 再按方向键才挪；一下都没挪就松开 ⌃，卡片留着变成普通的场景切换器（方向键 / Tab / 回车 / Esc）。
- **⌃Tab 换屏**：按着 ⌃ 时 Tab 以前到不了卡片（卡片不抢键盘）。现在卡片开着时由事件截取接管 ⌃Tab：换到下一块屏，选中项跳到那块屏现在的场景；平时 ⌃Tab 照常给浏览器。
- **已关的窗口还挂在卡片上**：场景缩略图和摆出来的时候都不再给关掉的窗口留格子。App 还开着、只是窗口关了 = 你不要它了，场景下次自动保存时去掉；整个 App 退出了（重启、退一下微信）场景继续记着，下次开了还认得。⌃ 卡片里不列一个窗口都摆不出来的场景。
- **⌥ + 滑动（转轮）一下换好几个**：触控板手指离开后的惯性滚动以前也在算。现在惯性不算，每一步要滑的距离加大到 90pt、两步至少隔 0.15 秒；转轮小框里的图标可以直接点。

### v0.6.5 场景归屏 + 四指滑跟手

- **四指滑卡、有时滑不动**：
  - 卡：卡片第一次浮出要 120~235ms（同步刷新窗口列表 ~50ms + 每次重建整排卡片 + 一次截几十个窗口的缩略图）。现在手指一搭上触控板 / 一按下 ⌃ 就预先刷新窗口列表，卡片界面只建一次，手势调出来时只补没有的缩略图。实测浮出 11~15ms。
  - 滑不动：以前每一帧都要求「横向位移 > 1.5 倍纵向」，手斜一点就一直不触发；手指偶尔被少认一帧会被当成抬手。现在走出一小段就定方向（横着就归 Weft，整个手势不再变），只看横向；少认几帧手指不算抬手；手指数变化时不跳格；滑得快多出来的距离留给下一格。每格距离 0.1 → 0.08。
- **场景归屏**（位置：laptop / ext1 / ext2，外接屏按从左到右）：
  - 切换器（⌃← →、四指滑、双击 ⌥）只列这块屏自己的场景 + 所属屏没接的场景（借住，标「扩展屏1 的 · 没接」）。Tab 换屏时卡片跟着换成那块屏的。
  - 点 Dock 切到场景里的窗口：场景摆到它所属的屏（那块屏没接才摆到当前屏）。新场景、单独场景、存成场景都归当时那块屏。组合按各场景所属的屏摆。
  - 换屏：切换器里 M /「换到另一块屏」，场景工作台里「属于」。工作台的场景列表按屏分组。
  - 插拔 / 换显示器：按位置记住每个位置上次摆的「自己的」场景（借住进来的不算）。某个位置又有屏了（插回同一台或换了一台），摆回它上次的场景；借住在别的屏上的场景回去，借出的屏回到它自己上次的场景。换了一台显示器时提示「扩展屏1（换成了 XX）摆回「…」」，不弹确认——同一个位置放的场景一般都一样。
  - 老场景按上次摆的屏自动归屏（实测 20 个：笔记本 14、扩展屏1 6）。
  - 实测：笔记本的卡片只有笔记本的场景，⌃Tab 后换成扩展屏1 的场景。插拔屏要真机拔线实测。

### 评估：能不能直接用 macOS 自己的桌面（Spaces）来做场景

结论：不建议作为主引擎，体验上能借的都已经借了。
- 好处：系统原生的切换动画、四指滑和调度中心完全一致；窗口不用藏到屏幕角落（没有调度中心乱飞、App 自己把窗口拉回来这类问题）。
- 卡点（都是系统限制，不是工作量）：
  1. 没有公开接口把别的 App 的窗口挪到另一个桌面。私有接口从 macOS 14.5 起对普通进程失效，yabai 这类工具要关 SIP 注入程序坞才能做到。不关 SIP 只能模拟「按住标题栏 + ⌃→」拖过去，看得见、慢、经常失败。「编辑场景 = 编辑桌面」的核心动作做不了。
  2. 一个窗口只能在一个桌面上。现在微信可以同时在「回消息」和另一个场景里，换成桌面就做不到。
  3. 只能摆当前桌面的窗口：别的桌面上的窗口辅助功能拿不到（现在卡片上标「别处」的就是这个），切过去以后才能排版，会先看到乱的再跳成整齐的。
  4. 新建 / 删除 / 命名桌面都没有接口，只能打开调度中心去点（Weft 删桌面就是这么做的，会闪一下）；桌面也没有名字。
  5. 「每块屏各自切」依赖系统设置「显示器具有单独的空间」，全屏 App 还会占掉一个桌面。
- 可选的折中（以后再说）：只做「只读」联动——你用系统桌面管窗口归属，Weft 给每个桌面起名、出带截图的卡片、到了这个桌面自动排版。窗口归属仍要你自己在调度中心里拖。


## v0.6.6 绑定 · 随手窗口 · AI 整理听要求（2026-11-08）

- **边缘侧栏不弹的根因**：息屏 / 唤醒时扩展屏会短暂从 NSScreen 列表里消失，系统把它上面的小窗口（1px 边缘感应条）推到主屏左下角；屏幕回来后布局「没变」（防抖后的 screenKey 一样），舞台分支只重排、不重建感应条 → 扩展屏那条叠在笔记本左边缘上抢鼠标，侧栏弹到了扩展屏。修：这种情况也重建感应条；感应条每 2 秒自检位置；碰到边缘后弹在鼠标所在的屏。
- **绑定**：`SceneCombo.linked`。一个场景只在一个绑定组里；`switchScene` 切到组里任一场景时，其余场景摆到它们各自的屏（屏没接就不摆）。切换器、四指滑 / ⌃←→、工作台、总控都走 switchScene；点 Dock 自动切换（handleActivation）不联动。老组合默认不联动，可手动打开。
- **随手窗口**：`settings.floatingApps`（bundleID）→ `StageManager.floatingApps`，`stageable` 返回 false：不上台、不被 sweep 藏、focusChanged 忽略（不开单独场景、不弹放置卡片）。设成随手时：台上的放手（`letGo`，不藏）、藏着的放出来、从场景里删掉该 App，只剩它的场景删除。
- **常驻 vs 临时**：场景成员 = 常驻；新开的窗口如果是随手 App 就浮着；不是的话照旧单独成场景 + 放置卡片，加进场景后关掉会自动从场景里去掉（App 还开着时），App 整个退出则保留（下次打开回到原位）。
- **AI 整理**：输入加 `user_request`、`existing_scenes`、`floating`、每个窗口的 width/height/min_width/fixed_size；提示词要求：要求优先但不硬凑、允许变体场景、多窗口按标题分、按格子宽度和 min_width 判断放不放得下、随手 App 列进 `floating_apps`。保存改成合并（以前整个替换会冲掉手建的场景），跨屏建议拆开后 `linked = true`，新场景按 AI 摆的屏归屏。
- 实测：绑定 ChatGPT（笔记本）+ 日历（扩展屏1）后两边互相带着切，没绑的 Telegram 不影响扩展屏；访达设成随手后两个访达窗口原地浮着、切场景不藏、「访达」空场景被删（测完已恢复原数据）；带要求跑了一次 AI 整理，给出「边聊边写（Claude+微信）」和「Claude 深度工作（Claude 单独）」两个变体、Chrome 按内容分到不同场景、访达建议随手。

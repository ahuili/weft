# 发布流程

每个确认好的版本走一遍。

## 一次性准备

1. `brew install gh && gh auth login`
2. 仓库主人已填好：`scripts/repo.env` 里 `GITHUB_OWNER=ahuili`，README 和安装脚本都指向 `github.com/ahuili/weft`。fork 后自己发布的话，把这几处的 `ahuili` 换成你的用户名。
3. 建两个公开仓库：
   - `ahuili/weft`：代码。`git remote add origin git@github.com:ahuili/weft.git && git push -u origin main`
   - `ahuili/homebrew-tap`：brew 配方（名字必须以 `homebrew-` 开头，用的时候写成 `ahuili/tap`）。
4. 签名证书：发布包用本机的「Weft Local Signing」自签名证书签。证书不变，用户更新后辅助功能权限就不会失效，所以**不要删这个证书**（钥匙串里导出备份一份）。

## 每个版本

1. 改 `VERSION`。
2. 在 `CHANGELOG.md` 顶部加 `## vX.Y.Z（日期）` 一节（发布说明直接取这一节）。
3. 提交：`git commit -am "vX.Y.Z"`
4. 先只打包看看：`scripts/release.sh`
   - 跑离线测试 → 编通用版 → `dist/` 里出 zip、dmg、SHA256SUMS、`weft.rb`、发布说明。
5. 确认没问题后发布：`scripts/release.sh --publish`
   - 打 tag、推送、建 GitHub Release 并上传安装包，更新 `homebrew-tap/Casks/weft.rb`。
6. 验证：`brew update && brew upgrade --cask weft`，或另一台 Mac 上 `brew install --cask ahuili/tap/weft`。

## 介绍视频

`promo/` 里是生成脚本（画面全是虚构的示例窗口，不含任何真实屏幕内容）：

```bash
cd promo && node render.mjs     # 需要本机 Chrome 和 ffmpeg；→ dist/Weft-介绍.mp4 和 assets/demo.gif
```

视频放进 GitHub Release 的附件，或在 README 里直接拖进去上传。

## 以后：Apple 公证

有 Apple Developer 账号（99 美元/年）后：

1. 用「Developer ID Application」证书签名（加 `--options runtime`）。
2. `xcrun notarytool submit dist/Weft-X.Y.Z.zip --wait`，然后 `xcrun stapler staple build/Weft.app`。
3. brew cask 里去掉 `postflight` 的去隔离那一段，安装脚本里的 `xattr` 也可以去掉。
4. 换证书会让老用户的辅助功能权限失效一次，在更新说明里提醒。
